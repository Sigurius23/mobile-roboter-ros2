bool getTransform(const std::string &source_frame,
                  const rclcpp::Time &time, Eigen::Isometry3d &T_out)
{
  try {
    auto tf_msg = tf_buffer_->lookupTransform(
        base_frame_, source_frame, time,
        rclcpp::Duration::from_seconds(0.1));
    T_out = tf2::transformToEigen(tf_msg);
    return true;
  } catch (const tf2::TransformException &ex) {
    RCLCPP_WARN_THROTTLE(…, 2000, …);
    return false;
  }
}

First, the signature. The function gets three things: the name of the sensor’s frame, the time the data was measured, and an empty transform called T_out, which it fills in. It returns true if that worked and false if not. In C++, bool means true or false, and the ampersand means the function works on the caller’s own variable instead of a copy, which is how it can fill in T_out. Next comes the try block: if something inside try fails, the program jumps to the matching catch block instead of crashing. Here the lookup fails when TF has no answer yet, right after startup, before the static transforms have arrived. Inside the try block we ask the TF buffer for the transform. lookupTransform does the asking and the answer is stored in tf_msg. The first two arguments are the frames: the target comes first, base_footprint, the robot; the source second, the sensor. In this order, the result moves sensor points into the robot frame. The third argument is the message’s own time stamp, and the last says how long to wait: at most a tenth of a second. Then transformToEigen turns the message into an Eigen isometry, a rotation plus a shift, and the function returns true. If anything went wrong, we land in the catch block, print a throttled warning, and return false.
