From source file to running node

Three files describe the package. Every dependency has to appear in all three places, or the build fails at that step.

  1. package.xml declares the dependenciesrosdep reads it to install missing packages, and colcon reads the build type ament_cmake.rosdep install --from-paths src -y --ignore-src
  2. CMakeLists.txt finds them and builds the executablefind_package locates each dependency, add_executable compiles the .cpp, and ament_target_dependencies adds include paths and libraries.colcon build --packages-select odom_transform
  3. install() copies the binary into the workspaceROS only finds what is in install/, not what is in build/.install/odom_transform/lib/odom_transform/odom_transform_node
  4. Sourcing adds the workspace to the environmentIt puts the package on AMENT_PREFIX_PATH. Your ~/.bashrc already does this in every new terminal.source install/setup.bash
  5. ros2 run starts itIt looks up lib/odom_transform/odom_transform_node under every sourced prefix.ros2 run odom_transform odom_transform_node

The ROS graph while it runs

Nodes never call each other directly. The bag player publishes topics, our node subscribes to two of them and publishes one transform, and RViz and rqt read the result.

QoS, as measured with ros2 topic info /odom --verbose The bag player publishes /odom as Reliable. Our node subscribes with SensorDataQoS(), which is Best Effort. That pairing connects. The reverse pairing would not: a Reliable subscriber gets nothing from a Best-Effort publisher.

The TF tree our node builds on

Our node adds one edge at the top. Everything below base_footprint comes from the bag's /tf_static and never moves relative to the robot. RViz chains these transforms to place the lidar points in my_odom.

Inside the node

The node is one class. Its constructor wires up the ROS interfaces, two callbacks do the work, and one helper sends the transform. All of it lives in src/odom_transform_node.cpp.

Steps 3, 4, 7, 8 · constructor

Wiring up

  • declare_parameter reads frame_name, use_imu and standstill_speed, so you can set them with --ros-args -p name:=value.
  • TransformBroadcaster publishes on /tf. The sheet links the static one, but that goes to /tf_static and is meant for frames that never move.
  • std::bind(&OdomTransformNode::on_odom, this, _1) turns the member function into a callback; _1 is the incoming message.
  • The IMU subscription and TF listener are only created when use_imu is true.
src/odom_transform_node.cpplines 26–62
  OdomTransformNode()
  : Node("odom_transform_node")
  {
    // Step 7: name of the new odom frame, e.g. --ros-args -p frame_name:=my_odom
    frame_name_ = declare_parameter<std::string>("frame_name", "my_odom");

    // Step 8 (optional): while linear.x == 0 (turning on the spot), take the
    // yaw rate from the IMU gyro instead of the wheel odometry.
    // In dlg_feldtage_24:cut the wheels still report ~0.02 m/s during the turn
    // on the spot, so a strict == 0 would almost never switch to the IMU.
    use_imu_ = declare_parameter<bool>("use_imu", false);
    standstill_speed_ = declare_parameter<double>("standstill_speed", 0.05);

    // TransformBroadcaster, not StaticTransformBroadcaster: the pose changes
    // with every odometry message. Static transforms go to /tf_static and are
    // meant for frames that never move (e.g. sensor mounts).
    tf_broadcaster_ = std::make_unique<tf2_ros::TransformBroadcaster>(*this);

    // Best effort is compatible with both reliable and best-effort publishers.
    odom_sub_ = create_subscription<nav_msgs::msg::Odometry>(
      "odom", rclcpp::SensorDataQoS(),
      std::bind(&OdomTransformNode::on_odom, this, _1));

    if (use_imu_) {
      // Only needed to rotate the gyro reading from the IMU frame into the
      // robot frame (static transform from the bag's /tf_static).
      tf_buffer_ = std::make_unique<tf2_ros::Buffer>(get_clock());
      tf_listener_ = std::make_shared<tf2_ros::TransformListener>(*tf_buffer_);
      imu_sub_ = create_subscription<sensor_msgs::msg::Imu>(
        "imu/data_raw", rclcpp::SensorDataQoS(),
        std::bind(&OdomTransformNode::on_imu, this, _1));
    }

    RCLCPP_INFO(
      get_logger(), "Publishing TF %s -> <odom child_frame_id>, IMU yaw rate %s",
      frame_name_.c_str(), use_imu_ ? "on" : "off");
  }
Step 3 · on_odom()

Integrating the pose

  • dt comes from the message stamps, not the wall clock, so it is right even when the bag plays faster.
  • If the new stamp is older than the last one, the bag looped: the pose resets to the origin.
  • With use_imu and the robot (nearly) standing still, ω comes from the averaged gyro samples instead of the wheels.
  • The midpoint rule uses the heading halfway through the time step, which is more accurate in curves than the plain Euler step.
θ_mid = θ + ω·dt/2 x += v · cos(θ_mid) · dt y += v · sin(θ_mid) · dt θ += ω · dt (wrapped to ±π)
src/odom_transform_node.cpplines 65–106
  void on_odom(const nav_msgs::msg::Odometry::SharedPtr msg)
  {
    // Some drivers leave child_frame_id empty; TF rejects empty frame names.
    base_frame_ = msg->child_frame_id.empty() ? "base_link" : msg->child_frame_id;

    const rclcpp::Time stamp(msg->header.stamp);
    if (last_stamp_ && stamp < *last_stamp_) {
      // Time jumped back: the bagfile started its next loop.
      RCLCPP_INFO(get_logger(), "Time jumped back, resetting pose to the origin");
      x_ = 0.0;
      y_ = 0.0;
      yaw_ = 0.0;
    } else if (last_stamp_) {
      const double dt = (stamp - *last_stamp_).seconds();
      const double v = msg->twist.twist.linear.x;
      double omega = msg->twist.twist.angular.z;

      bool omega_from_imu = false;
      if (use_imu_ && std::abs(v) < standstill_speed_ && imu_samples_ > 0) {
        omega = imu_yaw_rate_sum_ / imu_samples_;
        omega_from_imu = true;
      }

      if (dt > 0.0) {
        // Midpoint rule: use the heading halfway through the interval.
        const double yaw_mid = yaw_ + 0.5 * omega * dt;
        x_ += v * std::cos(yaw_mid) * dt;
        y_ += v * std::sin(yaw_mid) * dt;
        yaw_ = std::atan2(std::sin(yaw_ + omega * dt), std::cos(yaw_ + omega * dt));
      }

      RCLCPP_INFO_THROTTLE(
        get_logger(), *get_clock(), 2000,
        "x=%.2f m  y=%.2f m  yaw=%.1f deg  (v=%.2f m/s, omega=%.2f rad/s from %s)",
        x_, y_, yaw_ * 180.0 / M_PI, v, omega, omega_from_imu ? "IMU" : "odom");
    }
    last_stamp_ = stamp;
    imu_yaw_rate_sum_ = 0.0;
    imu_samples_ = 0;

    publish_transform(msg->header.stamp);
  }
Step 8, optional · on_imu()

Gyro into the robot frame

  • The IMU is mounted in frame imu_phidget, turned 90° about z. Its z axis still points up, but the code does not rely on that.
  • The first message looks up the rotation imu_phidget → base_footprint from /tf_static once and caches it in imu_to_base_.
  • quatRotate turns the gyro vector into the robot frame; only its z part (yaw rate) is kept.
  • The gyro measures angular velocity, even though the sheet says "Winkelbeschleunigungen".
src/odom_transform_node.cpplines 108–138
  void on_imu(const sensor_msgs::msg::Imu::SharedPtr msg)
  {
    if (base_frame_.empty()) {
      return;  // no odometry yet, robot frame unknown
    }

    if (!imu_to_base_) {
      if (msg->header.frame_id.empty() || msg->header.frame_id == base_frame_) {
        imu_to_base_ = tf2::Quaternion::getIdentity();
      } else {
        try {
          const auto t = tf_buffer_->lookupTransform(
            base_frame_, msg->header.frame_id, tf2::TimePointZero);
          imu_to_base_ = tf2::Quaternion(
            t.transform.rotation.x, t.transform.rotation.y,
            t.transform.rotation.z, t.transform.rotation.w);
        } catch (const tf2::TransformException & e) {
          RCLCPP_WARN_THROTTLE(
            get_logger(), *get_clock(), 5000, "No transform %s -> %s yet: %s",
            msg->header.frame_id.c_str(), base_frame_.c_str(), e.what());
          return;
        }
      }
    }

    const tf2::Vector3 gyro_imu(
      msg->angular_velocity.x, msg->angular_velocity.y, msg->angular_velocity.z);
    const tf2::Vector3 gyro_base = tf2::quatRotate(*imu_to_base_, gyro_imu);
    imu_yaw_rate_sum_ += gyro_base.z();
    ++imu_samples_;
  }
Step 4 · publish_transform()

Sending the transform

  • header.frame_id is the parent (my_odom), child_frame_id the robot (base_footprint).
  • The stamp is copied from the odometry message, so RViz matches it with the point clouds from the same moment.
  • TF stores rotations as quaternions; setRPY(0, 0, yaw) builds one from the 2D heading.
src/odom_transform_node.cpplines 140–158
  void publish_transform(const builtin_interfaces::msg::Time & stamp)
  {
    geometry_msgs::msg::TransformStamped transform;
    transform.header.stamp = stamp;
    transform.header.frame_id = frame_name_;
    transform.child_frame_id = base_frame_;
    transform.transform.translation.x = x_;
    transform.transform.translation.y = y_;
    transform.transform.translation.z = 0.0;

    tf2::Quaternion rotation;
    rotation.setRPY(0.0, 0.0, yaw_);
    transform.transform.rotation.x = rotation.x();
    transform.transform.rotation.y = rotation.y();
    transform.transform.rotation.z = rotation.z();
    transform.transform.rotation.w = rotation.w();

    tf_broadcaster_->sendTransform(transform);
  }

The robot drives about 2.5 m, stops, turns about −84° on the spot, then drives about 25 m straight. The wheels count about 4° less turning than the gyro measures. During the turn the wheels still report around 0.02 m/s, so the sheet's literal linear.x == 0 almost never hands over to the IMU; at 0.05 m/s it does. Over 25 m of driving, a 4° heading error already shifts the end point by about 1.6 m sideways, which is the 3.38 m versus 1.76 m in x.

Run it yourself

Open one Ubuntu terminal per command, with wsl -d Ubuntu-24.04 or the Ubuntu-24.04 entry in Windows Terminal. ROS and the workspace are already sourced.

Terminal 1 · play the bag (step 2) 
ros2 bag play $(marina resolve dlg_feldtage_24:cut) --loop --remap /tf:=/tf_old
Terminal 2 · start the node (steps 3, 4, 7) 
ros2 run odom_transform odom_transform_node --ros-args -p frame_name:=my_odom
Add -p use_imu:=true for step 8. Every 2 s it logs x, y, heading and where ω came from.
Terminal 3 · TF tree (step 5) 
ros2 run rqt_tf_tree rqt_tf_tree
Terminal 4 · RViz (step 6) 
rviz2
Set Fixed Frame to my_odom, then Add → By topic → /ouster/points PointCloud2, and Add → By display type → TF.

cd /mnt/e/aufgaben-public/ros2_ws && colcon build --packages-select odom_transform && source install/setup.bash
